# Task 1.9: FITS Viewer Remaining Feature Gap Closure

## Goal
Close remaining WPF-to-Avalonia FITS preview feature gaps by implementing missing viewer functions/items in small validated slices.

## Baseline and Target
- Baseline:
  - src/PreviewWindow.xaml
  - src/PreviewWindow.xaml.cs
- Target:
  - src/Rejector.Avalonia/Views/FramePreviewWindow.cs
  - src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs

## Gap Audit (Initial)
- Missing in Avalonia preview toolbar:
  - Open current frame in OS file manager (Explorer/Finder).
- Candidate next gaps to validate/port:
  - Viewer-local visibility controls parity from WPF preview surface.
  - Additional preview-window interaction shortcuts and status details.

## Implementation Slice 1
- Added `Open` button to Avalonia preview toolbar.
- Added cross-platform reveal logic in `FramePreviewWindow`:
  - Windows: `explorer.exe /select,"<file>"`
  - macOS: `open -R "<file>"`
  - Linux: `xdg-open "<parent-folder>"`
- Added user-facing status feedback when file is missing or open fails.

## Implementation Slice 2
- Added WPF-style viewer-local visibility controls directly to Avalonia preview toolbar:
  - `Accepted` toggle bound to `ShowAccepted`
  - `Rejected` toggle bound to `ShowRejected`
  - `Curvature` toggle bound to `IsCurvatureViewVisible`
- This restores quick frame-scope visibility control from the preview surface instead of requiring navigation back to the main window controls.

## Implementation Slice 3
- Ported WPF-style queued keyboard navigation behavior for Left/Right keys in `FramePreviewWindow`.
- Rapid key repeats now queue to a target index and process in sequence, reducing dropped navigation input while preview loading is still settling.

## Implementation Slice 4
- Added a preview-local `FILTERS` chip row in Avalonia `FramePreviewWindow`, bound to existing `FilterChips`.
- Chips are shown/hidden via `HasFilterChips` parity logic and toggle `IsSelected` directly, matching the WPF preview-window filtering workflow.

## Implementation Slice 5
- Added preview-local `Align` toggle in Avalonia `FramePreviewWindow`, bound to `IsAlignmentEnabled`.
- Implemented real alignment behavior in `MainWindowViewModel` preview rendering:
  - Carries `Rotate180`, `ShiftX`, and `ShiftY` from orientation analysis into `FrameResultContext`.
  - Applies orientation and pixel shift when alignment is enabled before rendering selected preview.
  - Persists/restores alignment metadata through session save/load.

## Implementation Slice 6
- Added a WPF-style right inspection rail in Avalonia preview window with:
  - Score card and direct keep/reject toggle action.
  - Inspection section with STF target background control and ROI edit toggle.
  - Metrics section bound to selected frame summary values.
  - Keyboard shortcuts section matching WPF preview guidance.

## Implementation Slice 7
- Completed functional STF control parity in Avalonia preview inspection rail:
  - Added `Auto Stretch` action.
  - Added bound `Shadows`, `Midtones`, and `Highlights` sliders with live values.
  - Wired STF changes to re-render selected preview.
  - Auto-stretch now computes from current `Target Background` and syncs slider values.

## Implementation Slice 8
- Re-implemented WPF-style top-right frame status badge in the preview right rail score card:
  - Status now shows a clear green keep or red rejected state for the current image.
  - Badge text is bound to selected frame rejection state label.
  - Badge remains directly clickable to toggle keep/reject for quick manual override.

## Implementation Slice 9
- Tightened score/status visual parity in the right rail score card:
  - Score value color now follows frame quality state (`GOOD` / `FAIR` / `POOR`) like the WPF behavior.
  - Keep/Rejected status badge prominence improved with centered text and consistent minimum width for clearer scanning.

## Implementation Slice 10
- Added missing WPF-like score progress feedback in the preview score card:
  - Progress bar now reflects selected frame score (`0-100%` of score out of 5).
  - Progress bar color tracks frame quality state.
  - Added compact quality label (`GOOD` / `FAIR` / `POOR`) next to the score for faster visual assessment.

## Implementation Slice 11
- Final visual parity pass against WPF `preview.png`:
  - Tuned toolbar chip colors for `Accepted` and `Rejected` to match WPF chip color semantics.
  - Tuned preview-local filter chip colors to match WPF blue filter chips and inactive state contrast.
  - Fixed zoom-reset regression after reject by preserving pending view state through transient null-image updates.
  - Reworked metrics rows with aligned label/value columns and indicator markers for clearer indentation/scanability.

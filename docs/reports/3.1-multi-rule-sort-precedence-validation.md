# Task 3.1: Multi-Rule Sort Precedence Validation

## Objective
Match the WPF multi-rule sort precedence so Avalonia results keep the same ordering when more than one sort rule is active.

## Baseline reference
- Legacy WPF comparator behavior in src/ViewModels/MainViewModel.cs
- Avalonia result ordering in src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs

## Changes made
- Added a shared core comparator in src/Rejector.Core/Services/FrameSortComparer.cs that applies sort rules in order and falls back to file-name ordering when all rules tie.
- Wired the Avalonia view model to use the shared comparator for visible results, including the expanded sort-field set.
- Matched WPF nullable-field behavior so missing observation dates and optional metrics remain last in both ascending and descending order.
- Added regression tests in tests/Rejector.Core.Tests/FrameSortComparerTests.cs for secondary-rule precedence, file-name fallback, and descending nullable ordering.

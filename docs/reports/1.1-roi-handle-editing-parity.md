# Task 1.1: ROI Handle Editing Parity

## 1. Objective
Port WPF ROI move and corner-resize semantics to the Avalonia preview window.

## 2. Task Contract
- Task ID: 1.1
- Epic: Preview parity
- User behavior to match: Drag ROI body to move; drag four corner handles to resize a square in image pixels; clamp ROI to image bounds; commit normalized ROI on release.
- Baseline references:
  - src/PreviewWindow.xaml.cs: RoiBody_MouseLeftButtonDown
  - src/PreviewWindow.xaml.cs: RoiHandle_MouseLeftButtonDown
  - src/PreviewWindow.xaml.cs: RoiOverlay_MouseMove
  - src/PreviewWindow.xaml.cs: RoiOverlay_MouseLeftButtonUp
- Target files expected:
  - src/Rejector.Avalonia/Views/FramePreviewWindow.cs
  - src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs
- Acceptance criteria:
  - Body drag moves without resizing.
  - Four handles resize from opposite anchored corner.
  - Resized ROI is square in displayed image pixels.
  - ROI cannot escape image bounds and respects minimum size.
  - Final normalized ROI is committed on pointer release.

## 3. Baseline Extraction Notes
WPF snapshots the normalized ROI and pointer position when editing begins. Move mode applies normalized deltas and clamps left/top. Resize mode anchors the opposite corner, chooses the larger pointer-axis delta for a square pixel side, clamps to image bounds, and commits on release.

## 4. Changes Made
- File: src/Rejector.Avalonia/Views/FramePreviewWindow.cs
- What changed: Added four WPF-styled corner handles, body-only move editing, opposite-corner anchored square resize in image pixels, minimum-size and image-bound constraints, live redraw, and commit on pointer release.
- File: src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs
- What changed: Added authoritative normalized manual ROI state, seeded it from the first analyzed frame's detected ROI, and exposed a clamped commit API.

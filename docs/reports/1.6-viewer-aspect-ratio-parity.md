# Task 1.6: FITS Viewer Aspect Ratio Parity

## 1. Objective
Preserve the source FITS aspect ratio in Avalonia viewer previews.

## 2. Task Contract
- Task ID: 1.6
- Epic: Preview parity
- Priority: HIGH
- User behavior to match: Non-square FITS images retain their original proportions at Fit, 1:1, and all zoom levels.
- Baseline references:
  - src/ViewModels/MainViewModel.cs: GetInteractivePreviewDimensions
  - src/PreviewWindow.xaml: PreviewImage Stretch=None
- Target files expected:
  - src/Rejector.Core/Services/RustafitsService.cs
  - tests/Rejector.Core.Tests/RustafitsServiceTests.cs
- Validation data:
  - `/Volumes/astronomy/RC/Bubble Nebula/LIGHT/R`
- Acceptance criteria:
  - Mono and color scaled previews use one uniform fit scale.
  - Neither rendered dimension exceeds its requested bound.
  - Source images are never upscaled by Core.
  - Rendered width/height ratio matches the source ratio within rounding tolerance.
  - Viewer and overlay geometry use the corrected rendered dimensions.

## 3. Baseline Extraction Notes
WPF computes one scale from the source longest side and derives both output dimensions from it. Core previously clamped width and height independently to 720, converting large non-square frames to 720 x 720 before Avalonia layout.

## 4. Changes Made
- File: src/Rejector.Core/Services/RustafitsService.cs
- What changed: Added one fitted-dimensions calculation and applied it to mono and color scaled preview rendering.
- File: tests/Rejector.Core.Tests/RustafitsServiceTests.cs
- What changed: Added a 1200 x 600 to 720 x 360 aspect-ratio regression test.

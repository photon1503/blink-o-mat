# Task 3.3: Bottom Status/Performance Detail Parity

## Objective
Match the WPF bottom status lifecycle during frame analysis and retain a detailed analysis performance summary in Avalonia.

## Task Contract
- Task ID: 3.3
- Epic: Sort, Filter, and Status Parity
- User behavior to match: The bottom status bar reports scan, load, finalization, completion, watch, and error states as they happen, with elapsed-time and throughput details after analysis.
- Baseline references:
  - `src/ViewModels/MainViewModel.cs`: `LoadFramesAsync` status lifecycle.
  - `src/MainWindow.xaml`: bottom status and performance indicator bindings.
- Target files expected:
  - `src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs`
  - `src/Rejector.Avalonia/Views/MainWindow.axaml`
- Acceptance criteria:
  - Bottom status changes at each WPF-equivalent analysis stage.
  - Completion status includes processed/skipped counts and elapsed time.
  - Performance detail includes elapsed time, frames per second, read throughput, and preview-cache count.
  - Status and performance text remain independently visible in the footer.

## Baseline Extraction Notes
WPF binds its single `Status` property directly in the bottom bar. `LoadFramesAsync` publishes scanning, per-frame loading, final comparison, filter construction, threshold initialization/application, completion, empty-folder, watch, and error states. Avalonia updates `StatusText` during analysis but only copies it to `BottomStatusText` after completion, so intermediate lifecycle states are absent from the footer.

## Changes Made
- `src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs`: publish every `StatusText` change to the bottom status bar.
- `src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs`: add scanning, comparison, filter, threshold-initialization, and threshold-application stages around the existing analysis work.
- `src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs`: prevent ROI and preview completion messages from replacing active analysis status.
- `src/Rejector.Avalonia/ViewModels/MainWindowViewModel.cs`: retain elapsed time, frames per second, read throughput, and preview-cache count as one performance summary when previews load.
